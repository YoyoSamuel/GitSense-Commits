# Activity Summary for 11/16/2026

## 6:25:07 PM
這份檔案為 `Robot/Plan/11.16plan.md`，記錄了 2026 年 11 月 16 日制定的開發計畫，旨在達成機器人 G1 在 Isaac Lab 模擬環境中進行「取放貨物 (Pick-and-Place)」的任務目標。

### 核心任務目標
本週目標為開發一段編寫好的 agent 程式，驅動 G1 機器人執行「走到 tote → 抓取 → 移動至放置點 → 放置」的完整流程。技術架構上，採用「下半身行走 RL + 上半身 IK 控制」的混合策略。

### 關鍵開發階段
*   **週一（環境與決策）：** 確認 Isaac Lab 環境配置與版本需求。核心任務為評估 `Locomanipulation` 環境的行動空間（Action Space），並依據機器人下半身對速度指令的反應能力，選擇合適的控制路徑。
*   **週二（技能開發與整合）：** 開發底層技能（如 `grasp_tote`, `walk_to` 等），並編寫硬編碼（hard-coded）的 agent 邏輯以串接上述技能。
*   **週三（成果展示）：** 整理系統架構、技術選型對應報告，並進行成果演示與問題反思。

### 重點資源參考
計畫中強調了四項外部技術資源的深度閱讀與轉化：
1.  **Decoupled WBC：** 用於規劃上下半身的分工架構。
2.  **RoboPlan：** 評估作為手臂 IK 或規劃器的可行性。
3.  **cuArms：** 考量未來多機器人或雙手協作的規劃邏輯。
4.  **CaP-X：** 指導技能 API 設計的抽象化，以優化後續 LLM 的應用效能。

### 應變計畫（備案）
為確保週三報告能順利進行，設定了明確的「停損點」：
*   若整合困難，則拆解為「站立取放」與「純步行」兩部分展示。
*   若抓取物體失敗，則採用 `fixed joint` 物理限制達成暫時性的展示效果。
*   若預設環境無法運作，則退守至 `FixedBaseUpperBodyIK` 環境進行測試。

### 執行原則
計畫強調「先懂為什麼，再動手」的原則，並要求開發者在執行過程中保持「每一步都自我檢核輸入輸出與成功定義」的紀律。同時明確列出了「暫時不讀」的領域（如 Telekinesis Tzara、模仿學習等），以聚焦於當前最急迫的開發目標。
