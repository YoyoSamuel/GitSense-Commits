This `README.md` details the "RoyalRoad Reader-Comment Generator," a pipeline designed to scrape chapters and reader comments from RoyalRoad, process them into training data, fine-tune a Qwen-based Large Language Model (LLM) using LoRA, and then use this model to generate authentic-sounding reader comments for any given chapter text.

The document outlines a clear, six-step pipeline:
1.  **`chapter_scraper.py`**: Scrapes top-rated fictions and their chapters into `chapters_dataset.jsonl`. It supports resuming crawls and includes polite delays between requests.
2.  **`comment_scraper.py`**: Retrieves reader comments for chapters, storing them in `comments_dataset.jsonl`. This script also supports automatic resumption.
3.  **`merge_comments.py`**: Processes raw reader comments by grouping them and using an Ollama-cloud model (`gemma4:31b-cloud`) to merge noisy comments into single, coherent, casual-toned entries, outputting `comments_merged.jsonl`. This step requires an `OLLAMA_API_KEY` to be set as an environment variable.
4.  **`prepare_sft_data.py`**: Combines chapters and the merged comments to create chat-format Supervised Fine-Tuning (SFT) examples, saved to `sft_data/train.jsonl`. It includes logic for truncating long chapters while preserving the beginning and end content.
5.  **`train_comment_sft.py`**: Fine-tunes the Qwen base model using QLoRA (4-bit base + bf16 LoRA) via TRL's `SFTTrainer`. It logs to Weights & Biases and supports resuming from checkpoints. It specifies model, epochs, batch size, LoRA parameters, and GPU requirements, noting the `HF_HOME` environment variable's importance.
6.  **`generate_comments.py`**: The final script that takes a chapter and generates reader comments using the fine-tuned model. It offers various flags to control generation mode (SFT or base model), input source (file, inline text, or index), metadata, and generation parameters like temperature and length.
